# V7.1.7 변경 사항

기준 소스는 검증된 V7.1.6이며, 기존 거래 전략·주문 유형·체결/잔고 상태 머신은 유지합니다. 변경은 로그 분석에서 확인된 계좌 인증 오류와 HTS 결과 진단을 중심으로 제한합니다.

## 1. 계좌/인증 단위 주문 잠금

- KIS 응답 코드 `40910000`, `IGW00002`, `90070000`을 계좌/API 신청정보 단위 오류로 분류합니다.
- REST 응답에서 해당 코드가 확인되면 `json/account_order_lock.json`에 잠금 정보를 원자 저장합니다.
- 잠금 상태에서는 공통 `OrderManager.submit()` 진입점에서 BUY·SELL 신규 주문을 모두 차단합니다.
- 재시작 후에도 잠금 상태를 복구합니다. 잠금 파일이 손상되거나 읽을 수 없으면 fail-closed 합니다.
- 최초 잠금 알림은 Telegram으로 1회 전송하고, 반복 주문 오류 알림을 억제합니다.
- 잔고·미체결·체결 대사는 계속 수행하며 watchdog는 계좌 잠금을 프로세스 장애와 구분해 degraded로 기록합니다.
- 잠금 이후 신규 취소 POST와 반복 취소 시도도 중단합니다. 기존 미체결 주문은 REST 조회만 유지하고, 필요하면 HTS에서 운영자가 직접 확인·취소해야 합니다.
- 시작 로그에 계좌번호/HTS ID를 일부 마스킹한 인증 환경과 credential fingerprint 일부를 남겨 새 설정이 실제 프로세스에 로드됐는지 확인합니다.
- 수동 해제 스크립트는 계좌/API 신청정보 및 REST·WebSocket 연결 검증 확인과 해제 사유를 요구하고, 기존 잠금 기록을 보존합니다.

## 2. 인증 캐시 격리

- REST 토큰과 WebSocket 승인키 캐시 fingerprint에 API 환경, App Key, App Secret 해시, CANO, 계좌상품코드, HTS ID를 반영합니다.
- 모의투자 계좌 또는 인증 구성이 바뀌면 이전 계좌에서 생성된 토큰/승인키 캐시를 재사용하지 않습니다.
- 실제 App Key, App Secret, 토큰, 승인키는 로그에 출력하지 않습니다.

## 3. HTS 조건검색 진단

- `seq="0"`을 임의로 잘못된 값으로 판단하지 않고 KIS 제목 API에서 받은 값을 그대로 전달합니다.
- `MCA05918`을 조건검색 결과 0건으로 정규화합니다.
- 0건은 정상 빈 결과로 기록하고, 조건명 미발견·응답 구조 오류와 구분합니다.

## 4. 유지한 기존 동작

- 매수·매도 전략 평가 및 YAML 조건
- 주문 수량 산정, 주문가능현금·미수 없는 매수가능금액 상한
- 주문 POST 불명확 상태와 종목별 uncertain 주문 잠금
- 부분체결·취소·REST 주문이력 대사
- 재진입 cooldown, 미체결 관리, WebSocket 체결 worker
- KRX 정규장 중심 운영
- TR별 내장 기본 호출 제한기와 공통 제한기를 유지합니다. `KIS_TR_RATE_LIMITS_JSON={}`는 TR 제한 비활성화가 아니라 사용자 재정의가 없다는 의미입니다.
- 현재 설정의 `ENTRY_MODE=ALL` 및 `STRATEGY_EVALUATION_MODE=ALL`, 주문금액 산정/현금 fallback 정책은 변경하지 않았습니다.

## 5. 검증 계획

- 전체 기존 pytest 회귀 테스트
- 계좌 오류 코드별 잠금, BUY/SELL 양방향 차단, 재시작 지속성, 손상 파일 fail-closed
- 일반 종목 오류는 계좌 전체 잠금으로 확대하지 않는지 확인
- MCA05918 빈 결과와 seq 0 보존 테스트
- 계좌 변경 시 인증 fingerprint 변경 테스트
- 잠금 해제 스크립트 문법/실행 테스트
- 패키지 생성 후 ZIP 무결성, 실행 권한, README/.env 문서 정합성 검사

모의투자 계좌에 새 API 신청정보를 연결한 뒤 REST 잔고 조회와 WebSocket 연결을 확인하고, 운영자가 잠금을 해제하기 전까지 신규 주문은 허용하지 않습니다.
