# V7.0.0 데이터 이전 및 소스 정리 감사

## 데이터 이전 정책

- 이전 대상은 `.env`, `state.json`, `uncertain_orders.json`, `cancel_orders.json`, `kis_tokens.json`, `holiday_config.json`, `manual_stop.json`, `monitoring_disabled.json`, `strategy_signals.jsonl`입니다.
- 일반 운영 로그와 PID/일회성 `start_trigger`는 이관하지 않습니다. PID는 이전 설치의 프로세스를 가리킬 수 있고, 시작 트리거는 이미 소비되었어야 하는 일회성 상태이기 때문입니다.
- JSON 파일은 UTF-8/JSON 구문과 상태에 필요한 핵심 구조를 확인합니다. `state.json`은 positions/cooldowns 구조, 불명확 주문 파일은 주문 종목/방향/수량/시간 필드, 취소 기록은 records 객체를 검사합니다. 중복 JSON 키도 거부합니다.
- `strategy_signals.jsonl`은 각 비어 있지 않은 줄이 JSON 객체인지 검사합니다. 대상이 없을 때만 복사하며, 대상이 존재하고 바이트가 다르면 이어 붙이거나 병합하지 않고 중단합니다.
- 복사할 파일이 있는 경우에만 `.migration_backups/<UTC timestamp>/`에 원본 바이트와 SHA-256 manifest를 먼저 기록합니다. 백업 디렉터리는 `0700`, 백업 파일/manifest는 `0600`입니다. 백업 검증이 끝나야 대상 복사를 시작합니다.
- 대상 파일은 원자적으로 생성하며 기존 파일을 덮어쓰지 않습니다. 복사 후 SHA-256과 JSON/JSONL 구문을 재검증합니다. 중단 후 재실행하면 동일 파일은 건너뛰고 누락된 파일만 복사합니다. 이미 동일한 파일만 남은 재실행에서는 새 백업을 만들지 않습니다.
- 사용자 지정 상대 파일 경로는 프로젝트 루트 기준으로 해석해 새 설치의 같은 상대 위치로 이전합니다. 설치 디렉터리 밖을 가리키는 상대 경로는 설치 위치가 바뀌면 의미가 달라질 수 있어 거부합니다. 사용자 지정 절대 경로는 현재 위치를 유지하며 복사하지 않고 백업/검증만 합니다.
- 사용자 지정 경로에는 데이터가 없지만 구버전 기본 경로에 파일이 남아 있으면 출처를 추정하지 않고 중단합니다. 구/신 경로에 서로 다른 데이터가 있거나 대상 파일 내용이 다를 때도 전체 사전검사를 통과하기 전에는 아무것도 복사하지 않습니다.
- 심볼릭 링크가 포함된 운영 파일 경로는 자동으로 따라가거나 덮어쓰지 않고 중단합니다.
- 원본 설치/파일은 삭제하거나 변경하지 않습니다. 외부 절대 경로에 있는 사용자 지정 파일은 새 설치와 기존 설치가 공유할 수 있으므로 이전 중에도 기존 프로세스를 먼저 중지해야 합니다.

## 소스/파일 사용 현황 검토

| 경로/파일군 | 내부 사용 현황 | 결정 |
|---|---|---|
| `strategy_engine/*.py` | 현재 `strategies.builder_engine`으로 위임하는 호환 shim이며 내부 핵심 경로에서는 직접 import하지 않음 | 외부 스크립트의 과거 import 호환을 위해 유지 |
| `compat/legacy_imports/*.py` | 애플리케이션에서 자동 로딩하지 않음. 디렉터리 README가 외부 레거시 import용 복사 어댑터로 설명 | 용도가 명시된 호환 자산이므로 유지 |
| 과거 릴리스의 문서 파일(현재 배포본에서는 제외) | 과거 릴리스의 변경/검증 기록 | 감사 추적 및 회귀 원인 추적을 위해 유지 |
| `config/my_entry_strategy.kis.yaml`, `config/my_exit_strategy.kis.yaml` | 설정 리로드 및 매도 경로에서 참조 | 유지 |
| `config/krx_holidays_2026.json` | 현재 연도의 정적 달력 데이터. 런타임 캐시 `holiday_config.json`과 별개 | 유지. 새 연도 달력은 별도 준비 필요 |
| `vendor/` | V7.0.0은 별도 Builder vendor 소스를 포함하지 않으므로 제거 |
| `tests/`, `smoke_test.py` | 회귀·오프라인 호환성 검증 | 배포/검증 기준이므로 유지 |

검토 중 삭제할 파일은 발견하지 않았습니다. “현재 내부 import 검색 결과가 없다”는 사실만으로 외부에서 사용할 수 있는 호환 shim이나 과거 검증 문서를 삭제하면 사용자가 의존하던 import/감사 이력이 깨질 수 있으므로 삭제하지 않았습니다.
