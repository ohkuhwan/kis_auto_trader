# V7.1.0 운영 및 전략 설정 매뉴얼

## 1. 안전한 시작 기준

- 기본 운영은 KIS 모의투자입니다. `KIS_PAPER=true`를 유지하고, 초기 설정 검증은 `KIS_ENABLE_TRADING=false`로 진행합니다.
- 실전 URL 선택과 주문 허용은 서로 다른 설정입니다. `KIS_PAPER=false`는 실전 서버를 선택하며, `KIS_ENABLE_TRADING=true`는 주문 전송을 허용합니다. 둘을 동시에 변경하지 마세요.
- `setup.sh`는 환경 준비용이며, 실제 KIS 주문·체결 안정성을 보장하는 검증을 대신하지 않습니다.
- 서비스 실행 계정이 로그 디렉터리와 상태 디렉터리에 쓸 수 있는지 확인합니다. `chmod 777`로 전체 파일시스템을 개방하지 않습니다.

## 2. 종목 후보 출처와 평가 엔진은 독립입니다

### 후보 출처: `ENTRY_MODE`

| 값 | 후보 출처 | HTS 조건명 필요 여부 |
|---|---|---|
| `HTS` | HTS 서버 저장 조건검색 결과 | 필요 |
| `BUILDER` | `BUILDER_SYMBOLS_FILE`의 코드 목록 | 불필요 |
| `ALL` | HTS 후보와 파일 후보의 중복 제거 합집합 | HTS 후보도 쓰려면 필요 |

`ENTRY_MODE`는 종목 후보를 가져오는 방법만 결정합니다. 후보를 BUY로 승인할지는 아래 평가 엔진이 결정합니다.

### 평가 엔진: `STRATEGY_EVALUATION_MODE`

| 값 | 매수 평가 | 전략 기반 매도 평가 |
|---|---|---|
| `KIS10` | 한투 10개 전략의 BUY 투표/점수 | 한투 10개 전략의 SELL 투표/점수 |
| `CUSTOM` | `my_entry_strategy.kis.yaml` | `my_exit_strategy.kis.yaml` |
| `ALL` | KIS10과 CUSTOM 모두 BUY여야 승인(AND) | 둘 중 하나라도 SELL이면 신호(OR) |

`ALL`에서는 각 엔진이 독립적으로 평가됩니다. BUY 후보 우선순위는 두 점수 중 낮은 점수를 사용하며, 서로 다른 점수 척도를 단순 합산하지 않습니다. 평가 오류가 있는 엔진은 BUY 승인에 사용할 수 없습니다.

## 3. 한투 10개 전략 설정

`config/strategy_profiles.yaml`은 다음을 한 곳에서 관리합니다.

- `strategies`: 각 전략 ID와 YAML 파일 경로. `enabled` 중복 스위치는 없습니다.
- `decision.buy.strategies`: BUY 투표 참여 전략과 전략별 `weight`.
- `decision.sell.strategies`: SELL 투표 참여 전략과 전략별 `weight`.
- `decision.buy.min_votes`, `decision.buy.min_score`: KIS10 BUY 판정 기준.
- `decision.sell.min_votes`, `decision.sell.min_score`: KIS10 SELL 판정 기준.

전략이 BUY 전용이면 BUY 목록에만, SELL 전용이면 SELL 목록에만 등록합니다. 양방향 전략은 양쪽 목록에 등록할 수 있습니다. 목록에 없는 전략은 해당 방향의 투표에 참여하지 않습니다. 각 전략 YAML의 `strategy.enabled=false`는 그 전략 파일 자체를 비활성화하는 호환 기능으로 남아 있습니다.

## 4. 사용자 정의 YAML

- `config/my_entry_strategy.kis.yaml`은 지표 정의와 `entry` 조건만 포함합니다.
- `config/my_exit_strategy.kis.yaml`은 지표 정의와 `exit` 조건만 포함합니다.
- `indicators[].alias`는 계산 결과에 붙이는 참조 이름입니다. alias만 새로 지정하면 기존 지원 type을 재사용할 수 있습니다.
- 지원 type은 `sma`, `ma`, `moving_average`, `simple_moving_average`, `ema`, `exponential_moving_average`, `rsi`, `volume_sma`, `average_volume`, `pct_change`, `return_pct`입니다.
- 기본 가격/거래량 이름은 `close`, `open`, `high`, `low`, `volume`입니다.
- 새로운 계산 종류(`type`)를 추가하려면 `strategies/builder_engine/yaml_engine.py`에 계산 로직과 테스트를 함께 추가해야 합니다. YAML에 알 수 없는 type을 적으면 평가 오류가 되어 신규 매수를 허용하지 않습니다.
- `entry.logic`/`exit.logic`은 `AND` 또는 `OR`이며, `conditions`에 실제 판정 조건을 적습니다. 설명용 alias는 자동 계산되지 않으며 `indicators`에 정의되어 있어야 합니다.

## 5. 1차/2차 손익절

1차 손익절은 전략 SELL 신호와 퍼센트 기준을 함께 충족해야 합니다.

- 손실 방향 1차: SELL 신호가 있고 손익률이 `-EXIT_STOP_LOSS_FIRST_PCT` 이하일 때.
- 수익 방향 1차: SELL 신호가 있고 손익률이 `EXIT_TAKE_PROFIT_FIRST_PCT` 이상일 때.
- 손실 방향 2차: `-EXIT_STOP_LOSS_HARD_PCT` 이하이면 전략 신호와 무관하게 강제 매도 요청.
- 수익 방향 2차: `EXIT_TAKE_PROFIT_HARD_PCT` 이상이면 전략 신호와 무관하게 강제 매도 요청.

현재 `.env.example` 기본값은 1차 손실 1.5%, 1차 수익 1.5%, 2차 손실 2%, 2차 수익 3%입니다. 실제 `.env.example`의 기본값을 확인하세요. 강제 매도는 주문 요청이지 체결 보장은 아닙니다. 주문 미체결, 부분체결, 주문가능수량 불일치, 장 운영시간 및 주문 가격 정책은 계속 적용됩니다.

이전 버전 상태에 남은 `strategy_risk`는 V7.1.0에서 독립 청산 트리거로 사용하지 않습니다. 청산 기준은 위의 공통 우선순위로 통합했습니다.

## 6. 재진입 및 API 안전

- `REENTRY_COOLDOWN_SEC`는 종목 청산 후 동일 종목의 즉시 재매수를 제한합니다.
- API 호출 제한기, rate-limit cooldown, 주문 제출 잠금, 불명확 주문 상태, REST/WebSocket 체결 중복 방지, 잔고 대사는 전략 평가 모드와 독립적으로 유지됩니다.
- 전략 점수는 경험적 지표일 뿐 수익 확률이 아닙니다. 모의투자에서 신호 로그와 실제 체결/잔고를 대조해야 합니다.

## 7. 설정 검증과 배포 후 확인

```bash
./scripts/reload_config.sh --validate-only
.venv/bin/python -m pytest -q
.venv/bin/python smoke_test.py
```

설정 변경 후에는 `STRATEGY_EVALUATION_MODE`별로 최소 다음을 확인합니다.

1. `KIS10`: BUY와 SELL 전략 목록 및 최소 투표 기준.
2. `CUSTOM`: 진입/청산 YAML의 지표 데이터 준비 여부와 조건식 결과.
3. `ALL`: BUY가 두 엔진 모두 BUY일 때만 승인되는지, SELL은 하나만 SELL이어도 신호가 되는지.
4. 1차 기준 미도달 시 전략 SELL만으로 매도되지 않는지, 1차 기준과 SELL 동시 충족 시 매도 요청되는지.
5. 2차 기준 도달 시 전략 신호와 무관하게 매도 요청되는지.
6. 부분체결/미체결/재시작/잔고 대사에서 중복 주문이나 상태 초기화가 발생하지 않는지.

이 ZIP만으로 Oracle Cloud Ubuntu와 proot의 실서버 자동 시작 성공까지 보장하지 않습니다. 두 환경에서 별도 설치·서비스·로그 권한 검증이 필요합니다.
