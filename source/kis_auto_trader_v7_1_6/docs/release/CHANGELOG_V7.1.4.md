# V7.1.4 변경 내역

기준 버전: V7.1.3

## 1. 매매 안전성
- `REENTRY_COOLDOWN_SEC` 기본/예제값을 900초에서 30,000초(500분)로 변경하고, 기존 `.env` 값이 900초여도 소스에서 최소 30,000초를 적용합니다.
- 전량 매도 체결 또는 WebSocket 체결통보 누락 후 잔고 대사에서 보유 0이 확인된 시점에 종목별 만료시각을 상태 파일에 즉시 저장해 재시작 후에도 재매수 제한을 복구합니다.
- 미체결 SELL 취소 요청 후 재평가 대기시간은 기존 `.env`가 10초로 남아 있어도 최소 60초를 적용하고, 취소 재시도 횟수에 따라 60, 120, 240초 등 지수형 대기(최대 900초)를 적용합니다.
- 부분 매도 체결은 재시도 누적을 초기화하고, 잔고 대사에서도 재시도 상태를 보존합니다.
- 주문 POST의 불명확 결과 자동 재전송 금지, 불명확 주문 영속화, 시작/종료 REST 대사, 수동 긴급 중지, 일일 손실 제한 및 신규 매수 안전 게이트는 기존 흐름을 보존합니다.

## 2. API 호출량 및 우선순위
- 동일 종목/기간 일봉 데이터를 기본 60초 캐시로 공유합니다.
- 매수 평가에서 KIS10/CUSTOM이 동일 일봉 snapshot을 공유하고, 보유종목 청산 평가에서도 두 엔진이 한 번 조회한 데이터를 공유합니다.
- HTS 조건검색과 사용자 종목 목록의 합집합/중복 제거 및 기존 후보 필터를 유지합니다. 후보 수 상한을 초과하면 HTS 원본 순서를 우선하지 않고 종목코드 정렬 기반 순환 평가를 수행합니다. 평가된 승인 후보는 기존대로 점수 내림차순으로 선택합니다.
- TR별 제한을 `KIS_TR_RATE_LIMITS_JSON`으로 설정할 수 있도록 추가했습니다. 미등록 TR은 공통 limiter를 따르며, 모든 호출은 공통 limiter도 통과합니다.
- 주문/취소, 잔고 및 주문·체결 대사 요청을 전략용 일봉 조회보다 우선 처리하도록 호출 대기열을 개선했습니다.

## 3. 전략 계산 및 설정 정합성
- 당일 고가와 저가가 같아 강한 종가 비율을 계산할 수 없는 경우 ERROR 대신 HOLD/평가 보류로 처리합니다.
- 전략 계산 데이터 부족은 `insufficient_data`로 분류하고 API 수집 실패/계산 오류와 구분합니다. 데이터 부족 전략은 신규 매수 승인에 사용하지 않습니다.
- 전략 파일 자체의 enabled 상태와 BUY/SELL 투표 참여 여부를 구분해 로그에 표시합니다.
- 사용자 제공 CUSTOM YAML, 전략 프로필, KIS10 전략 YAML 및 종목 목록을 릴리스 설정으로 반영했습니다. CUSTOM 활성 조건은 매수 RSI14 > 30, 매도 RSI14 >= 50입니다. 업로드 설정의 golden_cross는 SMA 3/10 및 OR 조건이므로 해당 사용자 설정을 보존했습니다.
- KIS10 10개 YAML의 `risk.stop_loss/take_profit/trailing_stop`은 실행 엔진에서 적용되지 않는다는 V7.1.2 주석을 복원했습니다. 이 값을 바꿔도 실제 공통 손익절 기준은 바뀌지 않습니다.
- min_votes/min_score와 가중 점수의 의미를 명확히 했습니다.

## 4. 운영 안정성 및 정보 보호
- WebSocket 가격 구독 동기화 작업을 직렬화해 동시 중복 구독 요청을 줄였습니다.
- WebSocket 재연결 generation을 감지하면 REST 주문/체결/잔고 대사를 수행합니다. 대사 실패 시 신규 매수 안전 게이트를 닫습니다.
- root로 생성된 control 로그 파일의 그룹/쓰기 권한을 로그 디렉터리 그룹에 맞춰 정규화합니다.
- Telegram 전송 실패 로그에서 예외 전문, URL, 응답 본문을 제거해 Bot Token/Chat ID/메시지 정보가 로그에 노출되지 않도록 했습니다.

## 5. 신규 환경변수
- `ENTRY_MAX_DAILY_CHANGE_PCT=25`: 당일 상승률 +25% 이상 신규 매수 제외.
- `ENTRY_MIN_DAILY_CHANGE_PCT=-15`: 당일 하락률 -15% 이하 신규 매수 제외.
- `DAILY_BAR_CACHE_TTL_SEC=60`: 일봉 캐시 TTL.
- `KIS_TR_RATE_LIMITS_JSON={}`: TR별 호출 제한 JSON.
- `SELL_RETRY_MAX_BACKOFF_SEC=900`: 반복 취소 SELL 재평가 최대 대기시간.

## 6. 설정 이전 시 주의
- 기존 서버 `.env`는 사용자 설정 보호를 위해 ZIP의 `.env.example`로 자동 덮어쓰지 않습니다. 기존 `.env`의 `REENTRY_COOLDOWN_SEC`, `SELL_RETRY_COOLDOWN_SEC`, `SELL_CANCEL_SETTLE_SEC` 값을 릴리스 기본값과 대조해 수동 반영해야 합니다.
- 실제 등락률 필드가 누락되거나 조회할 수 없는 경우 신규 매수 후보는 fail-closed로 보류합니다. 보유 종목 청산에는 등락률 필터를 적용하지 않습니다.
- `KIS_TR_RATE_LIMITS_JSON`은 공식 고정 한도를 임의로 가정하지 않습니다. KIS의 계정/상품별 최신 제한을 확인한 값만 입력하십시오.
- V7.1.4는 모의투자 검증용입니다. 전체 테스트 통과만으로 실전 전환 승인을 의미하지 않습니다.
