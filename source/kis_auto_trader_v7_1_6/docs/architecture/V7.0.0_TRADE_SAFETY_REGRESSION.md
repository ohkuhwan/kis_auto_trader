# V7.0.0 매매 핵심 로직 회귀 검증 기록

## 목적

런타임 데이터 경로 변경 및 프로세스 재시작 이후에도 기존 주문/체결 안전장치가 약화되지 않는지 오프라인 테스트로 확인한다. 본 검증은 모의 테스트 코드와 가짜 API를 사용하며, KIS API·소켓에 실제 연결하거나 주문을 제출하지 않는다.

## 검증 항목과 결과

| 영역 | 확인 내용 | 결과 |
|---|---|---|
| 상태 저장 | 포지션·평균단가·고가·쿨다운 저장 및 재시작 복구 | 통과 |
| 사용자 지정 데이터 경로 | `KIS_DATA_DIR` 이동 후 state / uncertain orders / cancel audit 경로 일치 | 통과 |
| 불확실 주문 | 주문 POST 결과가 불명확하면 재전송하지 않고 종목 잠금을 저장, 재시작 후 복구 | 통과 |
| 미체결 주문 | 재시작 후 브로커 미체결 주문 복구, 잔량과 누적 체결량 보존 | 통과 |
| 중복 체결 | 같은 WebSocket 통보와 오래된 누적 체결 통보를 중복 반영하지 않음 | 통과 |
| 부분/전체 체결 | REST 누적 체결량과 WebSocket delta를 조정하고, 포지션 수량·평균단가 반영 | 통과 |
| 매도 체결 | 부분 매도 수량 반영, 전체 매도 시 포지션 제거 및 실현손익·재진입 쿨다운 기록 | 통과 |
| 주문 취소 | 취소 응답만으로 완료 처리하지 않고 원주문·취소주문 이력 및 미체결 조회로 확인 | 통과 |
| 미확정 매도 | 출처/시간/방향/수량이 모호한 주문은 자동 해제하지 않고 잠금 유지 | 통과 |
| 손절/익절 | 하드 손절 우선순위, YAML 연동 소프트 손절·익절, 하드 익절 | 통과 |
| API 오류 | KIS 명시 거절과 rate limit 구분, 주문 POST 네트워크 예외는 한 번만 호출 | 통과 |
| 손상 파일 | state/uncertain/cancel audit 파일 손상 시 원본을 덮어쓰지 않음 | 통과 |

## 제한 및 미완료 사항

- 실계좌 주문, 실 API, 실 WebSocket 연결은 수행하지 않았다.
- `week52_high`는 공식 클래스의 현재가 API `w52_high` 대신 최근 252거래일 일봉 고가를 사용한다. 호출량을 줄이기 위한 문서화된 차이이며, 정확한 소스 parity가 필요하면 분당 API 예산을 다시 계산해야 한다.
- 이 검증 결과만으로 정식 릴리스 승인을 의미하지 않는다. 설치/패키지 검증 후 별도 승인 전까지 정식 ZIP을 생성하지 않는다.
